# Challenge the premise

If two or more fixes for the same problem have not resolved it, stop fixing and attack the premise.

1. Stop making further changes of the same kind.
2. List the assumptions behind the attempts: the cause of the problem, the requirement, the design, and the environment.
3. Check each assumption against evidence, such as output, logs, the code, or documentation, rather than reasoning from memory.
4. Take the approach the evidence supports, even if it means discarding earlier work.
5. Log the pivot with `log-your-work`.
